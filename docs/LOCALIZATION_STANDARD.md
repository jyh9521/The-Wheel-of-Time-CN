# 本地化工程标准

此文件落实维护者在项目创建时提出的标准。中文是第一个语言，而不是通用工具的默认技术假设。

## 分层与可复现性

1. locales/<locale>/ 保存译文、术语、语言配置；profiles/ 保存版本指纹与游戏机制。
2. tools/ 与 src/ 的文本、编码、资源、字体、补丁工具不得硬编码中文字符集或私人路径。
3. build.py --locale <locale> 是统一入口。原版与字体通过参数提供。
4. 原始文件只读；输出进入忽略的 build/。未知 SHA-256 拒绝修改。
5. 保留源条目 ID、原文散列、占位符、控制符、重复 occurrence；不能仅按英文文本合并回填。
6. 字库来自实际译文扫描、字体 cmap 覆盖检查、atlas/map/metrics 生成及包重读检查。
7. 二进制修改必须前置版本校验、后置散列校验、独立回滚验证。
8. 合成测试不依赖游戏；真实游戏集成、实机显示验收分别记录。

## 发布与文档

9. README 面向玩家与参与者；BUILDING、TRANSLATING、TECHNICAL、LICENSING 分别承担专门职责。
10. 重要偏移、长度单位、关联字段、崩溃条件、重复踩坑须记录；事实/推断/待验证分开。
11. 源码仓库不保存原版程序、完整原版资源、非再分发字体或发布包。Release 与 Git 源码分离。
12. 工具、译文、上游依赖、字体、游戏资源许可分别列出，保留贡献来源。
13. 首先研究现有上游；目前无上游研究仓库。本地阶段研究迁入后仍保留其发现与限制。
14. 优先最少侵入实现；不因中文便宜而把特殊处理写入通用层。
15. 当前阶段为少量 PoC 与工程工具链，不能标成完整汉化或其他语言实际兼容。

## 适配与后续门槛

16. 分辨率下限 1366x768，重点 1920x1080、2560x1440、3840x2160；320x240 不作为目标。
17. 写入分辨率配置不等于实际进入该显示模式。日志 best-match 与画面分别核验。
18. 字幕缺文、地图实例、硬编码 UI、视频字幕需独立任务；不能靠填满进度百分比掩盖遗漏。
19. 大规模翻译之前完成最小显示、重建、跨场景稳定性与术语评审。
20. 新语言新增配置与数据即可复用工具，但仍需自行提供覆盖字体并完成实机验收。
